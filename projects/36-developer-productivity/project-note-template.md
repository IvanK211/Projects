# Reference project note

## Problem and boundaries
State the goal without naming any actual organization, system, person, or site.

## Acceptance criteria
Define observable outcomes and explicit non-goals.

## Decisions
Record the options, chosen design, trade-offs, and a review trigger.

## Experiment log
Record only synthetic public examples here. Keep real measurements and operations in a separate private workspace.

## Test evidence
Separate syntax checks, fixture tests, lab validation, and production observation. Never claim one proves another.

## Follow-up work
Track one issue per reproducible defect or missing capability. Link public-safe notes only.
