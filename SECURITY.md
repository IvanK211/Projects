# Security policy

This is a reference collection, not a supported production service. No support email or organizational identity is embedded. Report a suspected issue through a private reporting channel configured by the repository maintainer. If no private channel exists, ask for one without posting credentials, customer data, internal paths or exploitable deployment details.

Describe the affected public file, minimal synthetic reproduction, expected behavior and potential impact. Do not run a proof against an organization or device without authorization. A proposed fix should retain offline-safe defaults, strict scope, validated inputs and clear failure states.

If a live credential is exposed, revoke or rotate it using the owning service before relying on repository cleanup. Never include the secret value in an issue, patch, test fixture or screenshot. The publication checklist is in `docs/PRIVACY.md`.
